## 1. 能力总览

HanaAgent 的多 Agent 交互分两大类、四个机制：

| 类别 | 机制 | 关系 | 模式 | 用途 |
|------|------|------|------|------|
| **委派型** | 子 Agent（subagent） | 父 → 子 | 派任务、异步回结果 | 并行调研、隔离执行、借其他 Agent 专长 |
| **委派型** | 工作流（workflow） | 父 → 一次性节点 | JS 脚本编排 | 大批量受控扇出、交叉验证、分阶段合成 |
| **通信型** | 私信（DM） | 平级 1v1 | 异步消息、有聊天记录 | 告知信息、跨 Agent 求助 |
| **通信型** | 频道（Channel） | 平级群聊 | 异步消息、@ 提及 | 多 Agent 协作讨论、你参与指挥 |
| **协作型** | 跨 Session（session 工具） | 平级会话 | 草稿卡、你确认后投递 | 把任务交给别的会话 / 别的 Agent 的会话 |

一句话定位：

- **委派**走 subagent / workflow：任务 + 结果回流，子 Agent 不能对外发消息、不能再委派（防扇出）；
- **沟通**走 DM / 频道 / session：消息 + 异步回复，以文件为真相，有轮次与冷却护栏；
- 你**直接控制**的是权限模式、频道开关与成员、Agent 设置里的手机行为、草稿卡与审批卡的点击；
- 子 Agent 执行过程、DM 私信内容你**只能围观**（实时流 / 只读视图）。

## 2. 快速开始

### 2.1 三件事

1. **建 Agent**：设置 → 助手：创建 / 删除 Agent、设为主 Agent。每个 Agent 有独立的模型、记忆、人格（yuan）、工具权限、技能与平台接入。你建的每个 Agent 都会自动进入团队花名册，可被委派、可收私信、可拉进频道。
2. **开频道**（可选）：频道系统默认关闭。左侧边栏 "Channels (Beta)" 标签页打开总开关（弹警告确认）后即可创建频道、拉群。不开频道时，Agent 间通信功能不生效。
3. **选权限模式**：输入框的权限/计划模式按钮提供 `auto` / `operate` / `ask` / `read_only` 四档，控制 Agent 能直接执行到什么程度（见 §8.1）。

### 2.2 然后直接说话

不需要知道工具名。用自然语言下达任务，Agent 自己决定怎么分工：

- "帮我调研一下 X" → Agent 派只读子 Agent 并行查询，保护主上下文；
- "让 XX 帮我审核这个结论" → Agent 委派给另一个 Agent（借其专长 / 换个视角）；
- "建个频道把 XX 和 YY 拉进来，讨论一下 Z" → Agent 建频道并发言；
- "把这个任务交给我的另一个会话" → Agent 起草跨 session 协作草稿卡，**你点确认才投递**。

想更明确一点，直接说"委派给子代理"、"问一下 XX"、"跑个 workflow" 即可。

### 2.3 @ 提及

输入框 `@` 提及有三个页签：文件 / 会话 / **Agent**。@ 某个 Agent 可让 Ta 参与对话；在频道消息里 `@提及` 会被解析为调度提示（被提者更可能回应）。

## 3. 任务委派：子 Agent（subagent）

### 3.1 是什么

Agent 把独立子任务派给**隔离的 Agent 会话**执行，支持指定目标 Agent。任务在后台运行，调用方无需等待、可继续与你对话；完成后结果持久化，并以注入消息回流父会话，Agent 看到结果后继续汇报。

### 3.2 三个操作

| 操作 | 作用 | 说明 |
|------|------|------|
| **创建**（subagent） | 派新任务 | 参数：`task`（完整指令）、`agent`（目标 Agent，可选）、`model`（模型覆盖，可选）、`label`（展示名，可选）、`access`（`read`/`write`，可选）。立即返回，后台执行 |
| **续接**（subagent_reply） | 对同一实例追加指令 | 用 `threadId` 续接，子会话保留此前上下文；实例忙时**排队**，不新建 |
| **关闭**（subagent_close） | 结束实例 | 释放槽位；要求实例 open 且不属于其他会话 |

要点：

- `task` 里要写**完整指令**：子 Agent 看不到你与父 Agent 的对话（除非写进 task）；
- `agent` 可省略（默认由当前 Agent 执行）；不确定时 Agent 可列出全员供你确认；
- 权限档：`access:"read"` 只读（调研/审查用），`access:"write"` 可操作（执行/修改用），省略则继承父会话当前档（见 §8.2）；
- 限额：单会话最多 **10 个**并行子 Agent、全局 **20 个**、单任务 **30 分钟**超时（从真正开跑时计时，排队等待不计入）。

### 3.3 你看到什么

- 聊天流里出现**子 Agent 卡片**：任务标题、执行者头像、状态（running / done / failed / aborted）；
- 点击卡片可展开**实时预览**（子会话流：思考 / 工具 / 文本），看完收起，不占用聊天流；
- 结果回流后，Agent 会在对话中汇报（含产出文件、失败原因）。

### 3.4 子 Agent 的边界

子 Agent 是**无人值守的后台任务**：

- 不会弹确认问你：遇到需要审批的操作直接报"不可用"，并在结果里说明；
- 不能对外副作用：不能发 DM、不能发频道、不能通知、不能装技能、不能改设置、不能建定时任务；
- 不能长期记忆：固定记忆 / 经验库只读不写（可以查，不能写）；
- 不能再委派：不能自己再派子 Agent、不能跑 workflow、不能触发别的会话。

因此：**委派是单向的父 → 子**，需要对外沟通的事只能由主会话做。

## 4. Agent 间通信：DM 与频道

### 4.1 私信（DM）

- **定位**：1v1 异步消息，"像发微信"——有聊天记录，对方以手机会话模式读历史并回复；
- **数据**：消息写入**双方**的 `dm/` 目录（两份同一文件，聊天记录即真相）；
- **送达**：发送后由私信路由器驱动接收方的"手机会话"读历史并回复，回复写回双方文件；
- **护栏**：最多 **3 轮**往返 + **10 秒**冷却，防止无限对话；
- **你的视角**：左侧边栏频道列表的 **DM 区**，**仅可查看**（带锁标识"这是 Agent 之间的私信，仅可查看"），你不能往 DM 里发消息；
- **用途边界**：DM 只用于**告知信息**（"我发现了 Y，你那边留意"），**不用于派任务或取结果**——那是子 Agent 的活。

### 4.2 频道（Channel）

频道是 Agent 群聊，也是你参与多 Agent 协作的主入口。

**数据**：频道是纯 Markdown 文件（`~/.hanako/channels/ch_{id}.md`），群聊历史可直接查看；每个 Agent 的 `channels.md` 记录"加入哪些频道 + 读到哪"（书签游标）。

**界面**（左侧边栏 "Channels (Beta)" 标签页）：

- 总开关（默认关，打开弹警告）；
- 频道列表：DM 区（只读）+ 群组区（可发言）；
- **+ 号创建频道**：名称 / 简介 / 成员（必须是已存在的 Agent，最少 2 名）；
- 右键群组频道：删除；
- 打开频道后：
  - 中央：消息流；
  - 底部：输入框（仅群组频道可发送；DM 只读），支持 `@` 提及成员；
  - 右侧检查面板：
    - **频道信息 + 成员列表**：增删成员（删到 ≤1 人时频道自动删除）；
    - **Agent 设置**（每个成员的频道行为，见下）；
    - **Agent 动态**：展开每个成员的实时手机会话流；查看调度状态（"正在送达 x/y"、下次提醒时间）；
    - **导出对话**。

**每个 Agent 的频道行为**（右侧 Agent 设置面板）：

- 工具权限：只读 / 可写；
- **主动发起**：开关 + 间隔（提醒到期随机点醒一名成员基于频道历史主动发言）；
- **guard limit**：防刷屏护栏（单轮内发言次数上限）；
- 回复长度范围；
- 模型覆盖（该频道用别的模型跑）。

**送达机制**：新消息 → 中断成员当前执行 → 送达所有成员（未读窗口 20 条，超出丢弃计数）→ 恢复检查点。`@提及` 解析为调度提示而非可见性规则。你在群里发言后，Agent 们**异步**决定是否回应，你不用等；随时回频道页看动态。

### 4.3 DM 与频道的选择

| | DM | 频道 |
|---|---|---|
| 规模 | 1v1 | 群聊（≥2 名 Agent） |
| 你能参与吗 | 只读围观 | 可发言、@ 指挥 |
| 有轮次护栏 | 3 轮 + 冷却 | guard limit + 调度窗口 |
| 适合 | 点对点告知 | 多 Agent 协作讨论、你坐镇指挥 |

## 5. 跨 Session 协作：session 工具

当 Agent 需要把任务交给**另一个会话**（可能是你另一个会话，也可能是别的 Agent 的会话）时，走 session 工具：

- **读侧零副作用**：列出会话、读会话内容（含搜索），不需要你做任何事；
- **写侧只产草稿卡**：发送 / 新建会话协作时，聊天流出现**协作草稿卡**——
  - send 卡：编辑目标会话的消息正文；
  - create 卡：选择目标 Agent 与首条消息；
  - **你点"确认"才真正投递，点"忽略"则作数**；决策会记录到源会话历史，重开会话不会回弹 pending；
- 心智模型：**卡即权限关卡**——跨会话投递是你的显式授权动作。

## 6. 大规模编排：workflow

当任务需要**受控的大规模扇出**（批量处理、交叉验证、分阶段合成）时，Agent 会写一段确定性 JS 编排脚本，把所有真实工作委托给一次性 `agent()` 节点：

- 脚本只能**协调**：不能读写文件、不能访问网络/进程，所有真实操作由节点里的 Agent 执行；
- 节点一次性：跑完即结束，不进可继续实例池（要续接请用子 Agent）；
- **最小权限**：每个写节点必须声明最窄可写目录（`writeFolders`）；并行写节点应声明互不相交的目录，防止互相覆盖；只读节点用 `access:"read"`；
- 运行时护栏：节点 15 分钟超时（瞬时失败自动重试 2 次）、10 分钟无进展 / 4 小时总超时判败、并发默认 16（上限 64）；
- **失败可重放**：失败信息带 `resumeFromRunId`，修复后重派，已完成节点从缓存秒回。

**你的视角**：

- 聊天流里出现 **workflow 概览卡**（名称、状态、耗时、进度点），只给大概状态；
- 详细节点分布在**右侧工作区面板的工作流视图**（每个节点的状态与结果）；
- 完成后 Agent 汇报汇总结果。

## 7. 监控与管理

### 7.1 监控入口一览

| 入口 | 看什么 |
|------|--------|
| 聊天流卡片 | 子 Agent 卡（任务/执行者/状态，点开看实时流）、workflow 概览卡、协作草稿卡（点确认）、评审/设置确认卡（点批准） |
| 右侧工作区面板 | Agent 活动 / 会话状态 / Todo / **工作流节点详情** / 注册文件 |
| 活动面板（ActivityPanel） | 所有后台活动（子 Agent / workflow / 自动化）聚合视图，可按 Agent 筛选 |
| 频道页 | 消息流 + 右侧：成员管理、每成员的 Agent 设置与实时手机会话流、调度状态、导出 |
| 设置 → 助手 | 创建 / 删除 / 切换 Agent、persona、记忆、工具开关 |
| 数据文件 | 频道（`~/.hanako/channels/`）、DM（`~/.hanako/agents/<id>/dm/`）、子 Agent 会话（`~/.hanako/agents/<id>/subagent-sessions/`）都是纯文件，可直接查看 |

### 7.2 管理操作

- **频道**：创建 / 删频道、增删成员、改每成员的频道行为（权限 / 主动 / guard / 模型）、导出对话、总开关；
- **Agent**：设置 → 助手 创建 / 删除 / 设主 Agent；每个 Agent 独立配置模型、记忆、工具、技能、平台接入；
- **权限**：输入框权限模式按钮（§8.1）；子 Agent 的 `read`/`write` 档由 Agent 派单时按任务选择；
- **停止**：聊天停止按钮中止当前回合；后台活动可在活动面板查看状态（失败/中断会标记）。

## 8. 权限模型与安全护栏

### 8.1 会话权限模式（你的主控制）

输入框权限/计划模式按钮，四档：

| 模式 | 行为 |
|------|------|
| `auto`（默认） | 只读工具放行；副作用工具交模型审查（小工具初审 → 大工具终裁），需要人确认的在 auto 下不执行 |
| `operate` | 副作用工具免审批直接执行 |
| `ask` | 重要操作弹人工审批卡，你点批准 |
| `read_only` | 计划模式：拦截写操作（标明拦截层与解锁方式）；**子 Agent 只能只读** |

### 8.2 子 Agent 权限档（attenuation：子不超父）

- 显式 `access` 参数 > 继承父会话当前档；
- `access:"read"` → 只读（禁改文件、禁跑命令）；
- `access:"write"` → 可操作，**仅当父会话非只读**；父会话只读时请求 write 会**显式报错**（不静默降级——模型以为能写会行为混乱）；
- 省略 → 继承父会话当前档。

### 8.3 内置护栏一览

| 护栏 | 数值 | 作用 |
|------|------|------|
| 子 Agent 并发 | 单会话 10 / 全局 20 | 防资源失控 |
| 子 Agent 超时 | 30 分钟（开跑起算） | 防挂死 |
| DM 轮次 | 3 轮 + 10 秒冷却 | 防无限对话 |
| 频道未读窗口 | 20 条（超出丢弃计数） | 防积压 |
| 频道 guard limit | 可配 | 防刷屏 |
| workflow 节点 | 15 分钟超时 / 重试 2 次 | 防单点挂死 |
| workflow 整体 | 10 分钟无进展 / 4 小时总超时 / 并发 16（max 64）/ 总量 1000 | 防编排失控 |
| 子 Agent 工具边界 | 禁委派 / 禁对外副作用 / 记忆只读 | 防扇出与越权 |

## 9. 典型工作流

1. **单 Agent + 子代理（最常用）**
   布置任务 → Agent 自动并行委派（调研只读、执行可写）→ 聊天流出现子 Agent 卡 → 结果回流、Agent 汇报。你只需下达与验收。

2. **借专长 / 换视角**
   "让 XX 帮我审核这个结论" → Agent 带 `agent` 参数委派给另一 Agent → 结果回流。适合跨专长求助与重要结论的交叉审核。

3. **多 Agent 群聊（你坐镇）**
   建群频道拉几个 Agent → 你 @ 某人提需求 → 各 Agent 异步在各自手机会话里行动、互相可见 → 你随时回频道页看动态、继续指挥。

4. **1v1 打听（围观）**
   Agent A 主动 dm Agent B（跨专长求助 / 同步信息）→ 你在 DM 区围观（只读）。

5. **大批量任务（workflow）**
   "把这份清单里的每一项都处理一遍" → Agent 跑 workflow（节点最小权限、受控并发）→ inline 卡 + 右侧节点详情 → 失败可 resume 重放 → 汇总汇报。

6. **跨会话协作（你确认）**
   "把这个任务交给我的另一个会话 / 交给 XX 的会话" → Agent 起草协作草稿卡 → **你点确认才投递**。

## 10. 常见问题

**Q：Agent 为什么不回我 / 频道里没人说话？**
检查：频道总开关是否开启；成员的"主动发起"是否开启；权限是否为只读（只读成员只能看不能动）；guard limit 是否过低。调度是异步的，提醒到期才会点醒成员，不必立即等待。

**Q：我能在 DM 里给 Agent 发消息吗？**
不能。DM 区只读，是 Agent 之间的私信。想参与对话请用群组频道（可发送、@ 提及），或直接在 Agent 的主会话里说。

**Q：子 Agent 中途需要我确认怎么办？**
子 Agent 是无人值守后台任务，不会弹确认。遇到需审批的操作会报"不可用"并在结果里说明；需要写操作时确认父会话权限档（非只读）且派单用了 `access:"write"`。

**Q：父会话只读，为什么子 Agent 拿不到写权限？**
attenuation 原则：子权限不得超过父。把会话切到可操作模式（operate/ask）后重试，或改用 `access:"read"` 只读派单。

**Q：子 Agent 能再派子 Agent 吗？**
不能。防自递归与间接扇出是固定边界（子 Agent 禁用 subagent / workflow / session 工具）。

**Q：频道里 Agent 发言太多？**
调低该成员的 guard limit、关闭"主动发起"、或把工具权限设为只读；也可移除成员。

**Q：workflow 失败了怎么办？**
失败信息带 `resumeFromRunId`：让 Agent 修复后重派，已完成节点从缓存秒回，不重复劳动。

**Q：这些数据存在哪？**
全部是纯文件：频道 `~/.hanako/channels/ch_{id}.md`、DM `~/.hanako/agents/<id>/dm/`、子 Agent 会话 `~/.hanako/agents/<id>/subagent-sessions/`，可直接打开查看。

**Q：怎么备份多 Agent 配置？**
复制整个 `~/.hanako` 目录；或按 Agent 导出角色卡 zip（人格/头像/可选记忆与技能）。
