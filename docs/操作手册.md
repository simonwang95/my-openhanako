## 1. 产品概述

### 1.1 HanaAgent 是什么

HanaAgent 是一个**有记忆、有灵魂的私人 AI 助理**：

- 作为助手，它易用：不需要复杂配置和晦涩术语，面向每一个坐在电脑前工作的人；
- 作为工具，它强大：记住你说过的每一件事，操作电脑、浏览网页、搜索信息、读写文件、执行代码、管理日程，还能自主学习新技能；
- 它支持**多 Agent 协作**：创建多个 Agent，各自拥有独立的记忆、人格和定时任务，可以群聊协作、互相委派任务。

如果你用过 claude code、codex、Manus 等 Agent，会在 HanaAgent 找到熟悉又新奇的感觉。

### 1.2 功能特性一览

| 特性 | 说明 |
|------|------|
| 记忆 | 自研记忆系统：近期记忆牢固，支持固定记忆、事实库、滚动摘要与"记忆编译"流水线 |
| 人格 | 人格模板 + 自定义人格文件，每个 Agent 有独立说话方式与行为逻辑；Agent 即文件夹，备份方便 |
| 工具 | 读写文件、一次性命令/持续终端会话、网页浏览、搜索、截图、媒体预览、Office 文档处理等 |
| 技能（SKILLS） | 兼容 SKILLS 社区生态；Agent 可从 GitHub 安装社区技能、自己编写并学会新技能 |
| 角色卡与技能包 | 角色卡 zip 导入/导出（白名单携带人格、头像、可选记忆与技能）；技能包可分组、拖拽、成组启用、单独导出 |
| 多 Agent | 多个 Agent 独立记忆/人格/定时任务，频道群聊协作、互相委派 |
| 书桌 | 每个 Agent 的工作台：放文件、写"笺"（便签，Agent 主动读取并执行）、拖拽、预览、变更监听 |
| 全屏媒体查看器 | 聊天/书桌中的图片、SVG、视频全屏预览：滚轮缩放、拖拽平移、`+`/`−`/`0` 快捷键、左右箭头切换相邻媒体 |
| 会话管理 | 聊天记录搜索（标题优先）、归档与恢复、项目分组、选中引用追问 |
| 定时任务与心跳 | Cron 定时任务（at/every/cron 三种触发器）+ 书桌心跳巡检 |
| 安全沙盒 | 双层隔离：应用层 PathGuard 四级访问控制 + 操作系统级沙盒（macOS Seatbelt / Linux Bubblewrap / Windows restricted token） |
| 插件系统 | 约定优先的可扩展架构：插件可贡献工具、技能、命令、HTTP 路由、页面、Provider 等；两级权限模型 |
| 多平台接入 | 同一 Agent 可同时接入 Telegram、飞书、QQ、微信、钉钉，远程对话与操作电脑 |
| 移动端与 LAN 前端 | Server 托管 `/mobile/` PWA；另一台桌面端可通过 LAN URL + 密钥连接同一 Server |
| 国际化 | 界面支持中文、英文、日文、韩文、繁体中文 5 种语言 |

### 1.3 平台支持

| 平台 | 状态 |
|------|------|
| macOS (Apple Silicon) | 已支持（Developer ID 签名 + 公证，可直接打开） |
| macOS (Intel) | 已支持 |
| Windows | Beta（安装包未签名，SmartScreen 可能拦截，见 §3.1） |
| Linux | 已支持（AppImage / deb） |
| 移动端 (PWA) | v0：同一 Server 的手机会话与工作台访问 |

### 1.4 技术栈

| 层级 | 技术 |
|------|------|
| 桌面端 | Electron 42 |
| 前端 | React 19 + Zustand 5 + CSS Modules |
| 构建 | Vite 7 |
| 服务端 | Hono + @hono/node-server（独立 Node.js 进程） |
| Agent 运行时 | Pi SDK |
| 数据库 | better-sqlite3（WAL 模式） |
| 测试 | Vitest |
| 国际化 | 5 语言（zh / en / ja / ko / zh-TW） |

## 2. 项目结构

### 2.1 顶层目录

```
core/           引擎编排层 + 各 Manager（Agent、Session、Model、Plugin、Skill 等）
lib/            核心库（记忆、工具、沙盒、Bridge 适配器、频道、书桌、技能等）
server/         Hono HTTP + WebSocket 服务（独立 Node.js 进程，约 45 个路由）
hub/            调度器、频道路由、DM 路由、事件总线（独立于当前会话运行）
desktop/        Electron 应用（主进程/预加载）+ React 前端
shared/         跨层共享工具（config schema、错误总线、模型引用、运行时路径等）
plugins/        内置系统插件（随应用打包：beautify、jimeng-cli、media、office）
skills2set/     内置技能定义（5 个）
packages/       插件 SDK 相关 npm 包（plugin-sdk / plugin-runtime / plugin-components / plugin-protocol）
scripts/        构建工具（server 打包、启动器、签名公证、发布）
tests/          Vitest 测试（约 760 个测试文件，风险驱动分层）
docs/           文档（本手册）
build/          安装器资源
tools/          辅助工具（npm-ea 等）
```

**运行模型**：Server 以独立 Node.js 进程运行（由 Electron 启动或独立启动），与 Electron 渲染进程通过 WebSocket 通信；Engine 是"薄门面"，协调各 Manager；Hub 负责后台任务（心跳巡检、定时任务、频道路由、Agent 间通信），独立于当前聊天会话运行。

### 2.2 运行时数据目录（HANA_HOME）

用户数据目录由 `HANA_HOME` 环境变量决定：**生产默认 `~/.hanako`，开发默认 `~/.hanako-dev`**。

```
~/.hanako/
├── agents/<id>/            # 每个 Agent 就是一个文件夹
│   ├── config.yaml         # 该 Agent 的全部设置（模型、记忆、技能、书桌等）
│   ├── identity.md         # 身份/人格（惰性落盘，按语言选模板）
│   ├── AGENTS.md           # 人格说明
│   ├── AGENTS.public.md    # 对外人格
│   ├── pinned.md           # 固定记忆（用户可直接编辑）
│   ├── channels.md         # 频道书签（加入哪些频道、读到哪）
│   ├── description.md      # 描述
│   ├── memory/             # 记忆：facts.db、today/week/longterm/facts.md、summaries/
│   ├── sessions/           # 会话 JSONL（含 archived/）
│   ├── desk/               # 书桌：cron-jobs.json、cron-runs/、笺注册表
│   └── avatars/            # 头像
├── skills/                 # 技能（每次启动从 skills2set/ 同步）
├── plugins/                # 用户安装的插件（plugins-dev/ 为开发槽位）
├── plugin-data/<pluginId>/ # 插件私有数据
├── channels/               # 频道文件（纯 Markdown）
├── studios/<id>/desk/      # Studio 化定时任务存储
├── user/
│   ├── preferences.json    # 全局偏好（跨 Agent 共享）
│   └── 用户档案
├── added-models.yaml       # 全局模型凭证
├── server-info.json        # 本地 Server 端口 + token（桌面端/CLI 连接依据）
└── runtime/pi-sdk/         # Hana 管理的 Pi SDK 运行时资源
```

> 所有 Agent 数据都是纯文件（YAML / Markdown / JSONL），用户可以直接查看和编辑。删除 Agent 会写墓碑文件 `.deleted-agent.json` 而非物理删除。

## 3. 安装与部署

### 3.1 下载安装（预构建包）

从 [Releases](https://github.com/liliMozi/openhanako/releases) 下载：

- **macOS（Apple Silicon / Intel）**：下载最新 `.dmg`。应用已通过 Apple Developer ID 签名和公证，可直接打开。
- **Windows**：下载最新 `.exe` 安装包。
  > **SmartScreen 提示**：安装包暂未经代码签名，首次运行时 Windows Defender SmartScreen 可能拦截，点击**更多信息** → **仍要运行**即可，属未签名版本的正常现象。
- **Linux**：下载最新 `.AppImage` 或 `.deb`。

### 3.2 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | macOS / Windows / Linux（见 §1.3） |
| Node.js（仅源码运行需要） | >= 24.12.0 < 25（CI 使用 24.15.0） |
| 模型接入 | 至少一个可用的 LLM API（OpenAI 兼容 / Anthropic 风格 / OAuth / Ollama 本地模型） |

### 3.3 从源码构建

```bash
git clone <仓库地址>
cd my-openhanako
npm install        # 安装依赖（postinstall 会 patch Pi SDK）
npm start          # 构建前端 + 启动 Electron
```

> **Native 模块说明**：Server 是独立 Node.js 进程（非 Electron 主进程），`better-sqlite3` 不需要 electron-rebuild；`build-server.mjs` 在目标 Node 运行时下安装依赖，ABI 自动匹配。

## 4. 首次启动

### 4.1 引导向导（6 步）

首次启动时，引导向导依次引导你完成：

| 步骤 | 内容 |
|------|------|
| 1. 语言 | 5 种语言选择；底部可选"连接已有局域网服务器"（URL + 密钥），用于另一台设备接入已有 Server |
| 2. 身份 | 你的名字（必填）、助手名字（默认 Hanako）、记忆开关 |
| 3. 供应商 | 预设供应商下拉（可搜索）或自定义（名称 / Base URL / API 类型：OpenAI 兼容、Anthropic）；填写 API Key（本地供应商免填）；**必须"测试连接"通过才能继续** |
| 4. 模型 | 自动拉取供应商模型列表（可搜索/手动添加，可编辑显示名、上下文长度、最大输出、图像/音频输入、推理等元数据）；须选择**对话模型** + **小工具模型**（轻量任务）+ **大工具模型**（记忆编译与深度分析） |
| 5. 工作区 | 选择默认主目录（`~/Desktop/Hanako`）或浏览自选 |
| 6. 教程 | 5 张功能卡片（记忆 / 技能 / 工作区"简" / 多 Agent 等），点击完成进入主界面 |

完成后系统写入设置并打开主窗口。

> 除三个必选模型外，设置页还可单独选择**视觉模型**，让文本模型通过 Vision Bridge 处理图片附件；Embedding 模型可单独指定供应商。

### 4.2 数据播种

Server 启动前会自动播种（`core/first-run.ts`）：

1. 创建 `~/.hanako/` 目录结构（`agents/`、`user/`）；
2. 创建默认 Agent `hanako`（完整目录结构 + config.yaml，记忆开启、心跳默认关闭）；
3. 每次启动将 `skills2set/` 同步到 `~/.hanako/skills/`；
4. 创建用户档案与 `user/preferences.json`（`primaryAgent: hanako`）。

对已有数据采用"分类处置"而非 fail-fast：损坏的默认 Agent 配置会先备份再重建；无效 Agent 目录跳过并记入诊断报告，不阻断启动、不动用户数据。

## 5. 日常使用

### 5.1 聊天界面

主窗口布局：标题栏 + 左侧会话侧栏 + 中央聊天页 + 右侧工作区面板（Agent 活动 / 会话状态 / Todo / 工作流 / 注册文件）+ 最右侧"简"书桌。

**会话侧栏**

- 聊天记录搜索：标题命中优先，必要时继续检索正文；
- 置顶会话、项目分组（建/改名/删文件夹）、按时间或项目排序；
- 新建会话；归档会话弹窗（归档后从设置入口恢复或永久删除）。

**消息块类型**

Markdown 流式消息、思考块、工具调用折叠组、资源卡、Agent 评审卡、事件卡、子 Agent 进度、工作流进度、音频、文件输出；支持查找条与时间线导航。

**输入框能力**

- `@` 提及：文件 / 会话 / Agent 三个页签；
- `/` 斜杠命令：服务端命令 + 技能命令；
- 附件：最多 9 个（`.skill` 文件直接安装为技能；书桌文件可直接附加；支持音频波形）；
- 选中文本进入引用卡片，追问时保留原文语境；
- 截图、语音录音；
- 模型选择器、思考等级、权限/计划模式切换；
- 上下文环：显示用量，可触发压缩/刷新；
- 发送 / 停止 / 转向；Agent 追问表单（需要补充信息时弹出）。

### 5.2 记忆

- 记忆是**人可读的 Markdown 文件**（`agents/<id>/memory/`），可随时查看；
- `pinned.md` 固定记忆：你写进去的内容会一直被记住；
- "记忆编译"流水线自动运行：会话摘要 → 每日日记 → 周汇总 → 长期记忆 → `memory.md`（受 token 预算约束，默认 2500）；
- 记忆采用高斯衰减：常提起的记忆不会消失，约两周未被想起的记忆自然淡出（`config.yaml` 中 `memory.*` 可调）；
- 记忆总开关：设置 → 助手 → 记忆（含自动整理）；经验库默认关闭（可能污染上下文，明确需要时再开）。

### 5.3 人格

- 每个 Agent 有人格文件（identity.md / AGENTS.md / AGENTS.public.md），设置页可直接编辑；
- 支持选择 yuan 人格底座（hanako / butter / ming 等模板）；
- 角色卡：可导入/导出为 zip（按白名单携带人格、头像、可选记忆和 Skills），方便迁移和分享。

### 5.4 书桌（工作台）

书桌是**你和 Agent 之间的异步协作空间**：

- 文件树 + Markdown 编辑器，支持新建文件/文件夹、拖拽、预览、执行日志；
- **笺（jian.md）**：把任务写成 `jian.md` 放进工作区，心跳巡检时 Agent 会自动领取、独立执行（不询问你），并用工具回写状态（进行中 / 完成 / 跳过 / 失败）；
- 工作区文件变更监听（快照差量，排除 Agent 自身输出目录防自触发）；
- 主文件夹：设置 → 工作台 中指定；默认 `~/Desktop/Hanako`。

### 5.5 多 Agent 与频道

**多 Agent**

- 设置 → 助手：创建 / 删除 Agent、设为主 Agent；
- 每个 Agent 独立配置模型、记忆、工具权限、技能、社交平台接入；
- Agent 之间可互相委派任务（子 Agent / DM）。

**频道**

- 频道是纯 Markdown 文件（`~/.hanako/channels/ch_{id}.md`），群聊历史可直接查看；
- 标题栏动态标签（可拖拽排序，超过 5 个收入下拉）；
- 创建频道（名称 / 简介 / 成员，最少 2 名 Agent）、增删成员、导出频道；
- 新消息会中断成员当前执行、送达后恢复；`@提及` 会解析为调度提示；
- 每个 Agent 可单独配置频道行为（模型覆盖、主动发言与间隔等）；
- 全局开关：设置 → 工作台 或 Agent 配置中的"频道"。

### 5.6 定时任务与心跳

**定时任务（Cron）**

- 任务存储已 Studio 化（`~/.hanako/studios/<id>/desk/cron-jobs.json`），运行历史在 `cron-runs/`；
- 三种触发器：`at`（一次性）、`every`（固定间隔）、`cron`（表达式）；
- 调度器每分钟检查到期（确定性代码层，不调 LLM），到期时创建后台 Agent 会话执行；单次执行默认 20 分钟超时；
- 自动化执行器把"什么时候触发"和"做什么"拆开：复杂任务由 Agent 后台执行，轻量提醒直接发通知，插件动作也可被计划调用；
- 自动化权限模式：设置 → 工作台（auto / 人工审批等）。

**心跳巡检**

- 每个有书桌的 Agent 独立运行，不依赖当前焦点 Agent；
- 默认**关闭**、默认间隔 31 分钟；在 Agent 的 `config.yaml`（`desk.heartbeat_enabled` / `desk.heartbeat_interval`）或设置页开启；
- 心跳做两件事：工作区文件变化检测 + 扫描工作区根与一级子目录的 `jian.md` 笺；
- 执行元数据记录在 activity store（上限 100 条，自动清理）。

### 5.7 会话管理

- 会话存储为 JSONL（`agents/<id>/sessions/<id>.jsonl`），纯文本可查看；
- 会话支持**分支**（条目树 + 分支头，切换分支即选叶）；
- 生命周期：active → archived → deleted；归档会话可从设置入口恢复或永久删除；
- 上下文压缩：三层机制（SDK 级 / 运行中压缩 / 按需 LLM 摘要），LLM 不可用时回退本地有损压缩；
- 会话项目：侧栏可将会话归入文件夹式项目。

### 5.8 全屏媒体查看器

聊天或书桌中的图片、SVG、视频，点开即暗色遮罩全屏预览：

- 滚轮缩放、拖拽平移；
- 键盘 `+` / `−` / `0` 缩放，左右箭头在同会话或同目录相邻媒体间切换。

## 6. 设置指南

设置页为独立窗口（也支持应用内弹窗形态），左侧导航 + 全局设置搜索。

### 6.1 导航总览

| 分组 | 内容 |
|------|------|
| 助手（agent） | 头像、名字、身份、AGENTS.md、yuan 人格、主模型/图像模型、记忆、经验、工具权限、导出角色卡、创建/删除 Agent、设为主 Agent |
| 我（me） | 用户头像、名字、用户档案 |
| 界面（interface） | 主题、字体、字号、纸张纹理、落叶特效、聊天宽度、Markdown 编辑器外观、硬件加速、会话列表单行、快捷键、语言、时区 |
| 通用（general） | 开机自启、保持唤醒、快捷聊天（快捷键/复用超时）、通知（聊天完成/巡检/定时任务） |
| 浏览器（browser） | Cookie 允许/清理、Agent 打开链接的行为（当前/新标签） |
| 工作台（work） | 心跳总开关+间隔、自动化权限模式、主文件夹、上下文文件注入（AGENTS.md / CLAUDE.md）、项目技能发现 |
| 技能（skills） | 用户/系统技能增删、启停、复制、拖拽安装、按 Agent 配置 |
| 连接器（mcp） | MCP 总开关 + 连接器（远程/本地、transport：auto/streamable/SSE、认证：none/bearer/OAuth/token） |
| 社交平台（bridge） | 微信/Telegram/飞书（国内·国际）/钉钉/QQ 凭证 + 测试 + 所有者用户 + 按 Agent 配置；全局权限模式、回执、富文本流 |
| 供应商（providers） | 模型供应商与凭证管理 |
| 多媒体（media） | 图像生成、视频生成、语音识别模型 |
| 分享（sharing） | 截图风格（字体/颜色/宽度/分段） |
| 插件（plugins） | 插件安装/启用/管理 + 插件市场 |
| 实验（experiments） | 压缩、人格、记忆、子 Agent 等实验项 |
| 访问与设备（access） | 局域网访问开关+端口、运行状态/URL、移动设备二维码、生成移动/桌面密钥、连接远程服务器、返回本地、配对设备与凭证吊销、账号与密码 |
| 安全（security） | 沙盒开关、沙盒网络、文件备份（保留 1/3/7 天、单文件大小上限、备份列表+恢复）、归档会话查看、网络代理（系统/手动/直连 + http/https/ws/wss/noProxy） |
| 关于（about） | 版本、检查/下载/安装更新、更新历史 |

### 6.2 配置作用域说明

配置字段分两种作用域（`shared/config-schema.ts` 为单一事实来源）：

- **global**：存 `user/preferences.json`，跨 Agent 共享（语言、用户名、时区、沙盒开关、网络代理、心跳总开关、频道开关、Bridge 权限模式等）；
- **agent**（默认）：存该 Agent 的 `config.yaml`，per-agent 独立（模型、记忆参数、技能列表、书桌、搜索供应商等）。

Agent 的 `config.yaml` 完整字段参考 `lib/config.example.yaml`（身份、API、模型、记忆、经验、搜索、技能、书桌、工作区上下文、频道等）。

### 6.3 安全设置详解

**沙盒**（设置 → 安全）

- 双层隔离：
  1. **PathGuard 路径 ACL**（应用层）：四级 `BLOCKED` / `READ_ONLY` / `READ_WRITE` / `FULL`。凭证文件（auth.json、models.json 等）不可读；Agent 配置与人格文件只读；Agent 的 memory/sessions/desk、工作区根可读写；删除操作要求最高级别；
  2. **操作系统沙盒**：macOS Seatbelt（生成 SBPL profile 执行）/ Linux Bubblewrap（缺 bwrap 时 fail-closed 拒绝直跑）/ Windows restricted token（独立 helper 进程按显式授权运行，**写隔离模型**：读取按当前用户权限自然发生）。
- 开关：`sandbox`（沙盒总开关，默认开）、`sandbox_network`（网络隔离，默认开；Windows 不支持网络隔离）。

**文件备份**

- 工具修改文件前自动备份原内容（仅文本、限大小），设置页可选保留天数（1/3/7）、单文件大小上限，查看备份列表并恢复。

**网络代理**

- 系统代理 / 手动代理（http/https/ws/wss/noProxy）/ 直连三选一。

**会话权限模式**

- `auto`（默认）：只读工具放行，副作用工具交模型审查；
- `operate`：免审批；
- `ask`：人工审批；
- `read_only`：计划模式，拦截写操作并标明拦截层与解锁方式。
- 审查由小工具模型初审、可升级大工具模型终裁；硬安全策略先行拦截凭证暴露、工作区外破坏性删除等。

## 7. 多平台接入

### 7.1 社交平台（Bridge）

设置 → 社交平台 中配置各平台凭证（支持扫码/测试连接），并指定所有者用户：

| 平台 | 接入方式 |
|------|----------|
| 微信 | 扫码登录，ilink HTTP 轮询 |
| Telegram | HTTP API |
| 飞书 | WebSocket 长连接 + 卡片流式渲染（国内/国际版） |
| 钉钉 | stream |
| QQ | 官方 Bot WebSocket 网关，分片上传富媒体 |

- Bridge 消息带平台上下文；通知（notify 工具）可回发到当前外部平台；
- 全局选项：权限模式（auto / 只读等）、回执开关、富文本流开关；
- 各平台可单独按 Agent 配置；
- 媒体投递：本机文件优先由各平台原生上传接口直传；`mediaPublicBaseUrl` 仅用于仍需公网 URL 的平台（Hana 不会自动开启公网 tunnel，公网入口必须由用户显式提供）。

### 7.2 移动端 PWA

- HanaAgent Server 托管 `/mobile/` PWA（含 Service Worker，支持更新检测与应用）；
- 登录两种模式：**设备访问密钥**（设置 → 访问与设备 生成）或**本地账号**（用户名 + 密码）；
- 可查看会话、继续聊天、管理工作台文件；窄屏（<860px）自动收抽屉，左右边缘滑动展开；
- 回前台/重连时自动补拉漏收消息。

### 7.3 LAN / 远程连接

- 设置 → 访问与设备：开启局域网访问（可指定端口），查看运行 URL，扫码或复制密钥；
- 另一台桌面端可"连接远程服务器"（URL + access key），消费同一套会话和资源；
- 配对设备管理：查看已配对设备、吊销凭证；
- 也可通过引导向导第一步的"连接已有局域网服务器"完成接入。

## 8. 插件

### 8.1 插件概念

插件是**约定优先**的可扩展单元：`plugins/<id>/` 目录 + `manifest.json`。插件可贡献：

- 工具（tools/）、技能（skills/）、命令（commands/）、Agent 模板（agents/）；
- HTTP 路由（routes/，可直接访问核心服务，PluginContext 注入；通过 Session Bus 与 Agent 对话、获取历史、管理 session）；
- Pi SDK extension（extensions/）、LLM Provider（providers/）；
- UI 页面 / 侧栏 Widget / 设置页 Tab；
- 配置 schema、chat surface、动态工具、后台任务。

### 8.2 两级权限模型

| 级别 | 说明 |
|------|------|
| `restricted`（默认） | 未声明 trust 一律按此。可贡献工具/命令/技能等；代码在主进程运行，限制的是"系统给的扩展接口"（事件总线仅 emit/subscribe/request） |
| `full-access` | 额外获得生命周期、HTTP 路由、Extensions、Providers、UI 页面、动态工具、后台任务。需 manifest 声明 `"trust": "full-access"` **且**用户在设置页开启"允许全权插件"（开关关闭时完全不加载） |

敏感能力按 manifest `capabilities` 声明 + 用户授权双重校验（未声明/未授权返回 403）。

### 8.3 安装与管理

- **安装**：拖拽文件夹或 zip 到设置 → 插件安装区 / 文件选择器 / 放入 `~/.hanako/plugins/`；
- **管理**：启用 / 禁用 / 删除 / 同名升级即时生效，无需重启；
- **私有数据**：`~/.hanako/plugin-data/<pluginId>/`；
- **插件卡片**会进入统一的消息块和历史回放。

### 8.4 内置插件（随应用打包，hidden）

| 插件 | 权限 | 功能 |
|------|------|------|
| beautify | full-access | 审美增强：Markdown cover 风格说明，把图片应用为 Notion 风格封面 |
| jimeng-cli | full-access | 通过官方 dreamina 命令提供即梦图片/视频生成 |
| media | full-access | Agent 侧媒体生成工具（基于 Hana Media Manager） |
| office | restricted | 读取 Office 文档 + Chromium 打印引擎导出 HTML→PDF |

### 8.5 插件开发

- 文档：`PLUGINS.md`（中文，含插件文件贡献规则）、`PLUGIN_SDK.md`；SDK 包在 `packages/plugin-sdk` 等；
- 开发循环：`plugins-dev/` 槽位 + EventBus（`plugin.dev.install/reload/…`）或 HTTP（`POST /api/plugins/dev/…`）；
- Agent 可见 dev 工具默认需用户在设置中开启；
- 内置技能 `hana-plugin-creator` 可引导你创建新插件（脚手架 + 开发向导）。

## 10. CLI（hana 命令行）

`hana` 是 **server-first** 的终端入口：连接本地 HanaAgent Server（读 `~/.hanako/server-info.json` 的端口 + token），在终端里查看状态、列会话和继续对话。

### 10.1 命令参考

```
hana serve [-- server args]        启动无头 HanaAgent Server（前台）
hana status                       查看本地 Server 与 Agent 状态
hana sessions                     列出最近会话（20 个）
hana continue [index|path]        续接一个最近会话（进入聊天）
hana chat [--plain]               打开聊天（--plain 为行式；非 TTY 时自动）
hana bundle pull                  拉取并激活最新 Web 前端（OTA）
hana bundle status                查看已拉取的 Web 前端状态
hana data diagnose                数据纪元只读诊断（stamp、journal、检查点）
hana data checkpoints             列出可用数据恢复检查点
hana data restore <transitionId>  从检查点恢复数据（需确认）
```

### 10.2 选项

```
--url <baseUrl>                   连接指定 HanaAgent Server
--token <token>                   该 Server 的 Bearer token
--session <path>                  在指定会话中聊天
--channel <stable|beta>           发布通道（serve / bundle，默认 stable）
--allow-data-downgrade            允许打开被更新内核触碰过的数据目录（有静默损坏风险）
--confirm-token <token>           非交互确认（必须恰好为 "restore <transitionId>"；
                                  stdin 非 TTY 时 data restore 必需，无法跳过）
--                                透传参数给 server
```

**行为说明**：

- `chat` / `continue` 在无 `--url` 且无存活 Server 时，会**自动拉起本地 Server** 并等待就绪；
- 交互聊天中支持 `/help`、`/sessions`、`/continue`、`/new`、`/status` 斜杠命令，Ctrl+C / Esc 中断；
- `serve` 启动前做"同宅互斥"探测，防止同一 `HANA_HOME` 双内核。

开发环境启动：`npm run cli`（等价于 `node scripts/launch.js cli`）。

## 11. 数据管理与备份

### 11.1 数据目录

所有用户数据集中在 `HANA_HOME`（生产 `~/.hanako`，开发 `~/.hanako-dev`，见 §2.2）。**备份 = 复制整个 `~/.hanako` 目录**（全部是纯文件）。

### 11.2 文件备份（自动）

- Agent 工具修改文件前自动备份原内容（文本文件、限大小），存于 `checkpoints/`；
- 设置 → 安全 → 文件备份：保留天数（1/3/7）、单文件大小上限、备份列表与恢复。

### 11.3 数据检查点（data epoch）

- data epoch 是**破坏性格式变更**的版本安全链：纪元戳（stamp）+ 过渡日志（journal）+ 检查点；
- 升级涉及数据迁移时，迁移前对受影响存储做字节可验证快照（SQLite online backup / 逐文件拷贝 + sha256），保留 2 份、上限 2GB；
- 启动时拒绝纪元降级（防旧内核打开新数据）；
- 恢复：`hana data diagnose` / `hana data checkpoints` / `hana data restore <transitionId>`（日志化恢复事务：先隔离原字节、拷回检查点、逐文件对账；非 TTY 必须带 `--confirm-token`）；
- 当前生产 epoch=1、迁移表为空——属预留基础设施。

### 11.4 迁移建议

- 迁移机器：复制 `~/.hanako` 到新机器同路径（或改 `HANA_HOME`）；
- 分享单个 Agent：导出角色卡 zip（设置 → 助手 → 导出角色卡）；
- 分享技能：技能包导出 zip；
- 分享插件：插件目录/zip。

## 13. 安全说明

- **双层沙盒**（§6.3）：应用层 PathGuard 四级 ACL + OS 级沙盒；Windows 为写隔离模型（读按用户权限自然发生）；
- **凭证保护**：凭证文件（auth.json、models.json、浏览器数据等）处于 BLOCKED 区域，Agent 不可读；
- **审批流**：副作用工具经模型审查（小工具初审 → 大工具终裁）或人工审批；硬安全策略拦截凭证暴露与工作区外破坏性删除；
- **插件两级权限**：full-access 需显式声明 + 用户开关；敏感能力双重校验；
- **技能安装审核**：默认开启（白名单、安全解包、安装前审核）；
- **远程访问**：Bearer token + WS ticket 鉴权；设备密钥/账号密码登录；grant 注册表 + 执行租约（非本地主体写文件前发 lease，可吊销）；
- **数据降级保护**：拒绝旧内核打开新纪元数据（`--allow-data-downgrade` 显式承担风险）；
- **安全政策**：见 `SECURITY.md` 与仓库 security 页面。

## 14. 常见问题

**Q：macOS 打开应用提示"已损坏"？**
应用已签名公证，正常情况可直接打开；若遇到提示，参考仓库 `desktop/如果提示已损坏请看这里.txt`。

**Q：Windows 安装时 SmartScreen 拦截？**
安装包暂未签名，属正常现象：更多信息 → 仍要运行。

**Q：技能装不上？**
默认对技能有安全审核，可在设置中关闭审核后再装。

**Q：Agent 写不了某些文件？**
沙盒按区域分级：凭证文件不可读、配置/人格文件只读、工作区与 Agent 数据目录可读写。需要更高权限时调整设置 → 安全 的沙盒级别，或切换会话权限模式。

**Q：如何备份？**
复制整个 `~/.hanako` 目录（开发环境为 `~/.hanako-dev`）。所有数据都是纯文件。

**Q：升级后数据出问题？**
`hana data diagnose` 诊断 → `hana data checkpoints` 查看检查点 → `hana data restore <transitionId>` 恢复。

**Q：想在终端里用？**
`npm run cli`（开发）或安装后的 `hana` 命令：`hana status` / `hana sessions` / `hana chat`。

**Q：手机怎么用？**
设置 → 访问与设备 开启局域网访问，用手机浏览器访问 Server 的 `/mobile/`，用设备密钥或账号登录。

**Q：支持哪些模型？**
OpenAI 兼容、Anthropic 风格、OAuth Provider 和 Ollama 本地模型等多类接入；已内置 OpenAI OAuth 登录（Anthropic 因封号风险暂不提供）。
